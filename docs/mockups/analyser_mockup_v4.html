    How the score works

    What it does
    Every measured recipe gets one number, lower is better, that the next-recipe method tries to minimise. PDI here is σ/R̄ of the fitted Schulz distribution, not the DLS polydispersity index. A fit of another shape than expected, or below the confidence limit, is not scored until you accept it.
    When to use
    Hit a size. The region and trade-off goals use the same size error but judge it against a band or a front.
    The maths
    score = ((R − R_t) / tol)² + w · (PDI / cap)
R_t = target diameter / 2,  tol = diameter tolerance / 2  (the optimiser works in radius)
one tolerance off the target counts as 1
    Read more
    docs/PARAMETER_SPACE_AND_CONVERGENCE.md

    Hit a size

    What it does
    Find one recipe whose particles meet the target diameter within the tolerance and the PDI cap, then stop.
    When to use
    You know the size you want.
    When not to
    You want to know every recipe that works: use Map the in-spec region.

    Map the in-spec region

    What it does
    Find the whole set of recipes that meet the spec, not just one.
    When to use
    You want a robust operating window.
    When not to
    You only need one good recipe; Hit a size is faster.

    Size vs PDI trade-off

    What it does
    Map the lowest PDI achievable at each size across a range: the Pareto front.
    When to use
    You want to know what is possible before choosing a target.

    Compare methods

    What it does
    Race next-recipe methods on the ground-truth simulator: same recipes, same score, several repeats.
    When to use
    Before a beamtime, to choose a method with evidence.
    When not to
    It never drives the reactor.

    Catalogue + BIC Standard

    What it does
    Fits every structure in the catalogue (sphere, core-shell, ellipsoid, cylinder, mass fractal, plus structure factors) and keeps the best by BIC. No AI. Reports an equivalent radius.
    When to use
    Default. Particles that may not be plain spheres.
    When not to
    You need sub-second fits per curve: use the sphere fit.
    The maths
    Each catalogue model is fitted; scale a and background b are solved exactly:  I ≈ a·F(q) + b
BIC = χ² + k·ln n   (lowest wins; k counts every free parameter)
R_eq = √(5/3)·R_g of the fitted shape  (= R for a sphere)
    How it scored
    Clean held-out: 100 % shapes, 0.3 % median size error. Hard held-out: 55 % shapes, 52 % sizes within 10 %. About 9 s per curve.
    Read more
    docs/benchmarks/FITTER_BENCHMARK_2026-10.md · Schwarz (1978), Ann. Stat. 6, 461 (BIC)

    Least-squares sphere Standard

    What it does
    Polydisperse-sphere form-factor fit by least squares (Schulz / log-normal); physics-based and interpretable.
    When to use
    You know the particles are spheres and want speed.
    When not to
    Rods, core-shell or aggregates: the size it reports is then meaningless.
    The maths
    P(q) = [3 (sin qR − qR cos qR) / (qR)³]², averaged over a Schulz or log-normal size distribution; least squares in log I
    How it scored
    Spheres: about 0 % size error. Other shapes: 50 % to 3000 % error. 0.2 s per curve.
    Read more
    docs/benchmarks/FITTER_BENCHMARK_2026-10.md

    ML regressor (k-NN) ML

    What it does
    A trained model predicts size / PDI directly from the curve: near-instant, spheres of radius 1 to 18 nm only.
    When to use
    A quick first look at sphere-like samples.
    When not to
    Sizes outside its library (radius 1 to 18 nm, so diameter 2 to 36 nm) or non-spheres.
    The maths
    k-nearest neighbours against a library of Schulz-sphere curves; confidence from the absolute fit residual
    How it scored
    Hard held-out: 20 % shapes (spheres only), 31 % median size error.
    Read more
    docs/benchmarks/FITTER_BENCHMARK_2026-10.md

    AI-assisted structure Agentic

    What it does
    The AI reads the curve's features, the sample context and the knowledge base, proposes up to 3 structures from the catalogue; each is fitted and the best by BIC wins. Falls back to Catalogue + BIC with no AI login.
    When to use
    Unusual curves, interactions or aggregation, where expert judgement helps.
    When not to
    Without an AI login it runs as Catalogue + BIC.
    The maths
    features + context + plot → AI names up to 3 catalogue models → each fitted → lowest BIC wins
(the AI never sets the numbers)
    How it scored
    Not yet measured with the real AI: python tools/fitter_benchmark.py --split hard_heldout --methods llm_assisted
    Read more
    docs/design/LLM_FITTER_PLAN.md · SasAgent, arXiv 2509.05363

    Random / Sobol search Standard

    What it does
    Space-filling Sobol baseline with no model. The honest reference: a method must beat this to earn its cost.
    When to use
    As the reference every method must beat.
    When not to
    A real campaign.
    The maths
    none (Sobol space-filling)
next = quasi-random point in the valid box (no model)
picks even coverage, the baseline every model must beat
    How it scored
    Measure it: Compare methods.

    Bayesian GP + EI ML

    What it does
    Gaussian-process surrogate with Expected Improvement. Balanced explore / exploit, and the default.
    When to use
    Hit a size; 5 to 30 runs; up to about 6 recipe parameters.
    When not to
    Many parameters or long campaigns: TuRBO.
    The maths
    Expected Improvement
EI(x) = (f*−μ)·Φ(z) + σ·φ(z),   z = (f*−μ)/σ;   next = argmax EI
picks the recipe expected to beat the current best by the most
    How it scored
    Measure it: Compare methods.
    Read more
    Jones, Schonlau, Welch (1998), J. Global Optim. 13, 455

    Bayesian GP + UCB ML

    What it does
    GP surrogate with a confidence-bound acquisition and an explicit explore / exploit knob (kappa).
    When to use
    You want an explicit exploration knob (κ).
    When not to
    You have no reason to tune κ; GP + EI needs no setting.
    The maths
    Lower Confidence Bound
LCB(x) = μ(x) − κ·σ(x);   next = argmin LCB
picks low predicted loss, with κ buying extra exploration
    Settings
    UCB κ (exploration): default 2.0 (higher = more exploration, lower = more exploitation)
    How it scored
    Measure it: Compare methods.
    Read more
    Srinivas et al. (2010), ICML

    TuRBO (trust-region BO) ML

    What it does
    Trust-region local BO: searches near the best point and grows or shrinks the region. Scales better in higher dimensions.
    When to use
    More parameters or a long campaign; searches near the best recipe.
    When not to
    Very few runs: the trust region has no time to adapt.
    The maths
    Expected Improvement in a trust region
next = argmax EI(x)  for x in trust region R;  R grows on a win, shrinks on a miss
picks the best EI point near the current best; the box adapts
    Settings
    Trust-region size (init): default 0.5 (fraction of the box the local search starts from)
    How it scored
    Measure it: Compare methods.
    Read more
    Eriksson et al. (2019), NeurIPS

    BAX (Bayesian Alg. eXecution) ML

    What it does
    Goal-aware (Bayesian Algorithm eXecution): maps the whole acceptance band (target size at low PDI), not just one optimum.
    When to use
    Map the in-spec region.
    When not to
    Hit a size: it spends runs on the band edge, not on one hit.
    The maths
    Band-membership entropy (InfoBAX)
p(x) = P(f≤τ) = Φ((τ−μ)/σ);   H = −p·ln p − (1−p)·ln(1−p);   next = argmax H
picks where 'in-spec?' is least certain, sharpening the band edge
    Settings
    Acceptance-band threshold (loss): default 2.0 (a recipe is 'in spec' when its loss ≤ this; BAX maps that set)
    How it scored
    Measure it: Compare methods.
    Read more
    Neiswanger, Wang, Ermon (2021), ICML (InfoBAX)

    Pareto GP + EHVI (size vs PDI) ML

    What it does
    Goal-aware (Expected Hypervolume Improvement): maps the size vs PDI trade-off across a diameter range. The real multi-objective acquisition for the Pareto goal.
    When to use
    Size vs PDI trade-off.
    When not to
    A single target.
    The maths
    Expected Hypervolume Improvement
EHVI(x) = E[ HV(P ∪ {f(x)}) − HV(P) ]  over two GPs (size, PDI);   next = argmax EHVI
picks the recipe expected to widen the size–PDI Pareto front most
    How it scored
    Measure it: Compare methods.
    Read more
    Emmerich, Giannakoglou, Naujoks (2006), IEEE TEC

    AI Advisor Agentic

    What it does
    The AI suggests the starting bounds and reviews progress every few runs; the optimiser picks every recipe. A suggestion inside the safety limits (reactor limits and search bounds) is applied automatically from the next recipe, logged and undoable; one outside them goes back to the AI with the limits, and is dropped if the second answer is still outside. Choose "ask me first" to approve each one instead. Measuring never stops for a review.
    When to use
    You want AI judgement with no change to how recipes are chosen.

    AI Co-pilot Agentic

    What it does
    The optimiser proposes its 5 best recipes; the AI picks one, using the chemistry and past results, and says why.
    When to use
    The recommended AI level: the acquisition maths still bounds every choice.
    The maths
    candidates = top-k by acquisition;  choice = AI(candidates, history, chemistry);  fallback = top-1
    How it scored
    Not built yet; will be raced against GP + EI in Compare methods.

    When not to

    Knowledge for campaigns

    What it does
    One knowledge set per chemistry, kept in the Knowledge tab: cards from literature (web search, papers) and your notes, your verdicts on past AI picks, and past campaigns. You add knowledge there; AI-drafted cards wait in Drafts until you approve them. Setup step 4 only chooses which set and which parts a campaign uses, and freezes them at Start. AI fitting uses the general SAXS knowledge instead.
    When to use
    Starting recipes: any method. Every pick: AI Advisor, Co-pilot or Pilot only. Verdicts are used by the AI only.
    When not to
    Safety limits. Those live only in the reactor limits; a card can narrow the search but never widen it. Text from papers or web pages is never passed to the AI as an instruction: only approved cards (setting, effect, numeric range, source) are.
    The maths
    per decision:  pick the 5 most relevant pieces (chemistry match, similarity to this curve or recipe)
→ the AI must name the pieces it used  → shown in Report, Decisions
    How it scored
    Each source stays on only if replaying past campaigns with it reaches good recipes faster than without it.
    Read more
    Design knowledge: Analyser → Knowledge tab, one set per chemistry system. General SAXS knowledge for fitting: shared with Guinier.

    How the design agent is harnessed

    What it does
    The AI next-recipe levels work inside a fixed harness, the same one the AI fitter uses: a fixed answer format, code-chosen knowledge, validation with a safe fallback, a version stamp and a full record of every decision.
    When to use
    Always, whenever an AI level chooses recipes.
    The maths
    Co-pilot:  shortlist = top-k by acquisition  →  AI returns {index, cited IDs, reason, expected size and PDI}
Pilot:     AI returns a recipe; it must pass ParameterSpace.valid, the pump limits and the trust region
invalid, uncited or timed out  →  the optimiser's top-1 is used and the fallback is logged
    How it scored
    Offline: replay of past real campaigns (tuned on one, judged on another) and the simulator race. Online: Report, Decisions shows how often the AI agreed with the optimiser, fell back, and beat its own prediction.
    Read more
    Meta-Harness (Lee et al., arXiv 2603.28052): keep full traces and accept a harness change only on held-out improvement.

    Report views

    What it does
    Convergence: best score so far. Surrogate: the GP's prediction and uncertainty across two recipe parameters. Trajectory: every recipe tried. Level set: the predicted in-spec region. Pareto front: best PDI per size.
